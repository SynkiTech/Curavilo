# CURAVILO

## Premium UI/UX Transformation, Interaction Design & Motion System

### Master Frontend Experience Prompt

You are now acting as the **Lead Product Designer, Senior UI/UX Designer, Interaction Designer, Motion Designer and Frontend Experience Architect** for Curavilo.

You are working inside the existing Curavilo healthcare SaaS project.

Do NOT rebuild the application from scratch.

Do NOT throw away working business logic, routes, authentication, database architecture, role permissions, workflows or existing functionality.

Your task is to **transform the existing Curavilo interface into a highly distinctive, beautiful, premium, memorable and extremely usable healthcare SaaS experience** while preserving the underlying functionality.

The target is not "pretty."

The target is:

> **A healthcare operating platform that feels so polished, intelligent and intentionally designed that the user immediately feels they are using a serious next-generation product.**

The interface should feel:

* premium
* sophisticated
* modern
* intelligent
* calm
* highly responsive
* visually distinctive
* operationally efficient
* human
* trustworthy
* memorable

It should NOT look like:

* a generic hospital management system
* a generic SaaS dashboard template
* a generic AI dashboard
* a fintech dashboard
* a Stripe clone
* a Linear clone
* a medical WordPress theme
* a Bootstrap admin template
* a collection of cards on a white background
* an "AI startup" full of glowing gradients

---

# 1. CORE DESIGN PHILOSOPHY

Design Curavilo around this idea:

> **Healthcare operations are constantly moving. Curavilo should visually communicate flow, coordination, intelligence and control.**

Curavilo is about:

**People → Patients → Services → Workflows → Tasks → Transactions → Data → Intelligence → Action**

The UI should subtly communicate movement and flow.

This should influence:

* navigation
* transitions
* workflow visualization
* dashboard animations
* loading states
* status changes
* notifications
* AI interactions
* charts
* queues
* cards
* icons
* backgrounds

Do not make the "flow" concept literal everywhere.

Avoid repeatedly using:

* chain-link symbols
* infinity symbols
* generic arrows everywhere
* circuit-board graphics

Instead use:

* directional motion
* flowing paths
* subtle moving particles
* coordinated icon motion
* connected state transitions
* soft spatial relationships
* animated lines
* dynamic progress
* intelligent feedback

# 11. MOTION SYSTEM

Create a **global Curavilo Motion System**.

Use JavaScript-driven motion, preferably:

* Motion for React / Framer Motion
* CSS transitions for simple state changes
* requestAnimationFrame for lightweight custom animation when appropriate
* SVG animation
* IntersectionObserver where useful

GSAP may be used selectively for complex orchestrated scenes if needed.

Do not introduce multiple animation libraries unnecessarily.

# 65. PERFORMANCE REQUIREMENT

Animation must not destroy application performance.

Target:

* smooth 60fps where practical
* minimal main-thread work
* GPU-friendly transforms
* avoid layout thrashing
* avoid huge DOM particle counts
* avoid continuous JS loops when CSS/SVG is sufficient

Use:

* transform
* opacity
* SVG transforms
* requestAnimationFrame carefully

Avoid animating:

* width
* height
* top
* left

when transforms can achieve the same effect.

Use IntersectionObserver to start effects only when visible where appropriate.

---
